# АвтоКлик

Сервис проверки, оценки и покупки автомобилей с пробегом. Один введённый госномер — и сервис сам опрашивает шесть источников, склеивает объявления одного авто на разных площадках, сравнивает цену с рынком и выдаёт готовый вывод, а не таблицу данных.

**Состояние: документация плюс работающее ядро.** Собраны расчёт ремонта под пробег, нормализация и склейка объявлений, оркестрация проверки на фикстурах, API и веб-клиент с витриной и карточкой. Живых адаптеров площадок нет намеренно — правовой статус такого сбора не закрыт (см. [открытые вопросы](docs/06-открытые-вопросы.md)). Всё, что описано в документации как архитектура и стек, по-прежнему предложение, требующее утверждения.

## Как запустить

```bash
pip install -e ".[dev]"
PYTHONPATH=. python3 examples/run_web.py   # витрина на http://127.0.0.1:8000/
python3 -m pytest                          # тесты
```

Витрина (`/`) — лента объявлений с оценкой цены относительно рынка. С неё открывается карточка автомобиля (`/car/{id}`): сверху бесплатный расчёт ремонта под пробег, ниже — предложение проверки по базам. API проверки живёт отдельно, под `/api/v1`, документация — `/api/v1/docs`.

Данные — фикстуры сценария из дизайн-концепции, а не выдача живых площадок.

## Модули

| Пакет | Что делает |
|---|---|
| `avtoklik/knowledge` | болячки моделей, модель отказов по пробегу, ожидаемая стоимость ремонта |
| `avtoklik/matching` | нормализация госномеров и VIN, склейка объявлений одного авто на разных площадках |
| `avtoklik/collector` | контракт источника, оркестрация опроса с дедлайном, извлечение фактов из текстов |
| `avtoklik/service` | витрина, сборка карточки товара и вердикта проверки |
| `avtoklik/api` | HTTP-контракт проверки, стрим прогресса |
| `avtoklik/web` | серверный рендер витрины и карточки, дизайн-токены, адаптив |

## Что нужно знать, прежде чем читать

Единственный вход для всей документации — дизайн-концепция «АвтоКлик — дизайн-концепция и userflow»: 6 флоу, 28 экранов, 4 персоны, 7 нарисованных корнер-кейсов.

Презентация ссылается на ТЗ «Платформа анализа авторынка» пунктами 5.1–5.9, разделом 4, разделом 12 и Приложением Б, **но самого ТЗ у команды нет**. Везде, где документы говорят о содержании ТЗ, это реконструкция по косвенным упоминаниям, и в текстах это помечено.

## Три вещи, которые стоит решить до начала разработки

1. **Легальный доступ к данным Авито, Авто.ру и Дрома.** На них построены три из пяти заявленных дифференциаторов продукта. Эти же компании — конкуренты и правообладатели баз данных.
2. **Договорённость с ДомКлик и Сбером.** Сбер ID, СберPay и брендирование стоят в макетах как архитектурные зависимости, а бесплатный трафик экосистемы — единственный канал, на котором сходится unit-экономика.
3. **Холодный старт ML-оценки.** Оценка заявлена на пяти экранах, а на день запуска нет ни одной подтверждённой сделки. Сбор данных нужно запускать за 60 дней до релиза — это нельзя добрать потом.

Подробности — в [концепции](docs/01-концепция.md), §6.
